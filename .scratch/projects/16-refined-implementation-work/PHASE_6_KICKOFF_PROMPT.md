**WHAT PHASE 6 IS (one line):** collapse the per-write-method Python post-commit sequences into **one** `_after_commit(delta)` hook so no write path can diverge, make **every** write path publish (today `discard` commits a revision but never publishes), turn the bus `Delta` into a thin **id-level** wrapper over the Phase-3 `CommitDelta` (no graph walk to reconstruct ids from paths), and **remove the writer-blocking overflow policy** so a slow/dead subscriber can never stall the writer.

**THIS PHASE CLOSES THESE DEFECTS:**
- **Defect #2** (transaction split across the lock boundary) — Phase 5 closed the *in-lock* half (stage→publish-last→rollback under the native `Mutex`). Phase 6 closes the **bus / Python-post-commit-path half**: one `_after_commit` hook + a bus that delivers id-level deltas in revision order and never blocks the writer. **After Phase 6, mark #2 fully DONE.**
- **Defect #6** (one write path forgets to publish) — `discard` (Python `session.py`) commits a revision, calls `_apply_graph_delta(result)`, and **returns without publishing** (verified: no `_publish_delta`). The single `_after_commit` hook makes "publish every revision" true by construction. **Mark #6 DONE.**
